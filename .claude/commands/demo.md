# Чек-лист записи демо

Прогони этот чек-лист перед записью демо (сценарий — `docs/demo-script.md`, лимит 2 минуты).

## Перед стартом

- [ ] `docker compose --profile full up -d` — весь стек зелёный (`docker compose ps`)
- [ ] `.env` заполнен и в кадр не попадает
- [ ] Grafana открыта (http://localhost:3000), дашборд с CPU/диском виден
- [ ] Telegram открыт, чат с ботом виден
- [ ] Диск перед симуляцией заполнения: `df -h` — запас есть, порог 85% достижим
- [ ] Таймер запущен (или таймкоды будут в монтаже)

## Две части записи

- [ ] Часть 1: симуляция диска → сырой алерт → разбор «руками» с таймером
- [ ] Часть 2: cleanup → повтор симуляции → Telegram-алерт с объяснением (что случилось / причина / что проверить)

## После записи

- [ ] Cleanup: удалить временные файлы симуляции (`incident-sim` cleanup-команды)
- [ ] Зафиксировать замеры: время разбора в обеих частях, ложные срабатывания
- [ ] Сообщение агента из Telegram — скриншот для кейса (без чувствительных данных)
- [ ] Обновить «Результат» в README (команда `/case-update`)

## Не показывать в кадре

- `.env`, токены, ключи
- Внутренние названия с работы
- Личные чаты Telegram — только чат с ботом
